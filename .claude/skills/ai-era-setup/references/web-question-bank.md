# 拷问问题库（配合 /grill-with-docs）

两轮。第一轮是根上的分叉，第二轮依赖第一轮答案。每题附推荐答案；用户授权“按推荐来”时先复核，改口的地方明说。

## 第一轮（根）

**Q1 机器是“闸”还是“影子”？** (a) 影子：只观察打标签，UI 不动，拦不住任何事；(b) 闸：所有副作用经 `dispatch`，blocked 就不发，等于按页重写；(c) 先影子后闸，逐页升级，现有 E2E 当安全网。
➡️ (c)；机制先在**最小页面（登录）**验通，随后**主链核心**第一个做闸；服务端已有真实状态的那台机器优先。

**Q2 机器的表达形式？** 手写 `interpret` if/else（一页一份）vs 数据表 + 一个通用解释器 + 具名 guard。
➡️ 数据表。一张表生成契约 JSON、场景清单、文档矩阵、story 骨架——这是把打点和 E2E 缝到一起的那根线。

**Q3 oracle 要不要可执行？** 全部可执行 / P0 可执行、其余散文标 `planned`。
➡️ P0 可执行。否则回到“矩阵先写满再实现”的横切。

**Q4 打点的单位和去处？** 单位 = 一次转移 `{trace_id, request_id?, feature, from, to, event, status, reason?, input, effects}`。(a) 只测试模式落库；(b) 生产全量；(c) 生产只落副作用 + blocked + unknown，其余采样。
➡️ (c)。blocked 证明闸在工作，unknown 是没建模的世界。前提：`trace_id`（一次意图）与 `request_id`（一次 HTTP）关系定死；遥测走自己的限流，不吃用户写预算。

**Q5 “AI 自动 E2E”指哪一种？** (a) 从表 BFS 生成路径 + 通用驱动 + 不变量 oracle，确定性；(b) LLM 写用例；(c) (a) 为主，LLM 只处理 unknown 队列（提议，人拍板）。
➡️ (c)。生成器第一版只证明“生成集合 == 手写覆盖集合”；驱动列（怎么触发）和夹具列（前置状态）是第二版。

**Q6 范围和顺序？** 盘点所有有状态的东西（不是页面），分几批、第一批哪三个。
➡️ 三批：① 主链核心 + 跨页旅程 + 运行时；② 登录升闸 + 发布/保存对话框；③ 权限/列表/管理员。

**Q7 组件层的前提是拆壳。** 逐个拆、拆一个跑一次 E2E，还是一次拆完？
➡️ 逐个拆；拆的顺序就是批次顺序，拆哪个哪个顺便变成闸。

**Q8 生产遇到 unknown？** (a) 只记录，动作照常；(b) 阻止。
➡️ (a)。测试模式 unknown = 失败；生产进管理员“未建模转移”队列，一周清一次。

## 第二轮（依赖第一轮）

- **guard 怎么拿事实**：只看机器自维护的 `facts`（输入是否合法、是否在途、是否勾选），不读 DOM/DB——DOM/DB 是 oracle 的对象。
- **trace_id 与 request_id**：一次意图一个 trace（客户端手势时生成，跨页用 sessionStorage），`X-Trace-Id` 随请求上送；一次 HTTP 一个 request_id；两个都落到每一行。新意图 = 离开初始状态 或 行上标 `effects.intent`。
- **跨页旅程**：算一台机器，页面机器与旅程机器并存。
- **需要真实数据的事件**：表里写 `fixture` 名，E2E 端同名夹具，组件层用注入回放。
- **对答案怎么做**：答案卷（期望序列）+ 一个 UI 镜像组件；只有镜像组件与机器的绑定需要看源码。
